\section*{Appendix A: Research Overview}
\addcontentsline{toc}{section}{Appendix A: Research Overview}

This section provides a concise summary of the thesis by answering ten guiding questions.

\subsection*{1. What is the central question?}
Which implicit neural representation architecture works best for three-dimensional occupancy reconstruction, and what architectural properties determine success?

\subsection*{2. Why is this question important?}
Practitioners face many architectural choices when using neural networks for 3D shape representation, but lack clear guidance on which methods work best. Understanding what makes certain architectures succeed helps both method selection and future architecture design.

\subsection*{3. What evidence/data (variables) are needed to answer this question?}
We need reconstruction quality metrics (IoU, accuracy, precision, recall, F1) for multiple architectures on the same test shape. We also need information about each architecture's properties (spatial compactness, frequency compactness, adaptivity) and computational costs (training time).

\subsection*{4. What methods are used to get this evidence/data?}
We implemented eight INR architectures (SIREN, WIRE, GAUSS, FINER, Fourier Features, INCODE, MFN, FR) with identical network structure and training procedures. Each method was trained on the Nefertiti bust mesh and evaluated on a dense $256^3$ grid.

\subsection*{5. What analyses must be applied to the data to answer the central question?}
We compared reconstruction metrics across methods to establish performance ranking. We grouped methods by architectural properties and computed average performance for each group to identify which properties correlate with success.

\subsection*{6. What evidence/data (values for the variables) were obtained?}
Over four seeds, evaluation IoU ranged from $0.9148 \pm 0.0082$ (GAUSS) to $0.9677 \pm 0.0009$ (Fourier Features), with INCODE tied at the top ($0.9674 \pm 0.0022$) and a middle group (SIREN, FR, FINER, WIRE) near 0.952--0.956. A controlled ablation on the Fourier frequency scale gave 0.9632 at $\sigma = 1.0$ against 0.7966 at $\sigma = 10.0$.

\subsection*{7. What were the results of the analyses?}
A one-way ANOVA rejected equality of means ($p \approx 10^{-16}$), and Holm-corrected Welch $t$-tests placed Fourier Features and INCODE in a top tier that is statistically indistinguishable internally but significantly ahead of every other method. MFN and GAUSS trailed clearly and both failed to fit their own training data, indicating optimization difficulty rather than a representational limit. The frequency-scale ablation moved accuracy by 16.7 points --- an order of magnitude more than any gap between architectures --- while improving training accuracy to 1.0000.

\subsection*{8. How did the analyses answer the central question?}
They identified a genuine best tier (Fourier Features and INCODE) that a single run had missed, while showing that architecture is not the largest lever: one hyperparameter within a single method outweighed every architectural difference. The two weakest methods were shown to fail for optimization rather than representational reasons. The grouped property analysis proved unsound: the frequency-compactness advantage flips sign when the single weakest method is removed, and the best tier pairs a compact method with a non-compact one.

\subsection*{9. What does this answer tell us about the broader field?}
Single-run comparisons are unreliable for differences of a percentage point: our own single run reported a different leader and a spurious near-tie that repeated runs overturned. Architectural property taxonomies of the kind proposed in recent surveys require validation that a grouped mean over few methods cannot provide, and comparisons holding depth and width fixed should report parameter counts, since matching architecture does not match capacity.

\subsection*{10. Did the thesis answer the question satisfactorily?}
Yes, with appropriately bounded confidence. Repeated runs identified a best tier for this task and separated it from the field with a significance test, while the study is candid about what it cannot resolve: the middle group's internal ordering, the influence of an eight-fold spread in parameter counts, and generalization beyond a single mesh and single-shape fitting. Its most transferable result is methodological --- a direct demonstration that a single run would have reported the wrong ranking.

\subsection*{B.6 Code and Data Availability}

The complete implementation is available at:

\url{https://github.com/AhmedKElshahed/INR}

The repository includes all architecture implementations, the training and evaluation script (\texttt{train\_3dv2.py}), configuration files, and the exact dataset used for our experiments (\texttt{nefertiti\_dataset.npz}). Per-seed metrics are recorded in \texttt{results\_3d\_seeds.csv} and per-epoch training curves in \texttt{logs\_3d/}. The results table, error-bar figure, and significance test in this report are generated directly from that CSV by \texttt{aggregate\_seeds.py}, so the reported numbers cannot drift from the underlying data.

To reproduce the four-seed benchmark:

\begin{verbatim}
git clone https://github.com/AhmedKElshahed/INR.git && cd INR
pip install -r requirements.txt
python train_3dv2.py --mesh nefertiti.obj --epochs 500 --seeds 0 1 2 3
python aggregate_seeds.py
\end{verbatim}

Note that \texttt{generate\_data.py} has been revised since the dataset was produced and will not reproduce it exactly; the committed \texttt{.npz} should be used instead.
